# RaWMoCS Playground

A local-only DIMACS signed-complex WMC front end. The site assembler requires a pin to an official non-draft stable release ID, Git revision, distribution archive and provenance SHA256. It refuses unconfigured or candidate input and does not read temporary Actions artifacts. After the first same-release WASM distribution passes corresponding-source/license review and is published, update release.json to pin that release. The existing Rust science workflow automatically runs the official-release Playground smoke on relevant main pushes. The explicit manual Playground suite remains available. The real Chromium gate checks 16 analytical counts and failure/stop/re-entry; Pages deployment remains gated on the resulting exact site and explicit deployment configuration. No GPMC, QuPRS or remote solver dependency.

The existing footer provides the required third-party notice and a link to the exact official release containing corresponding source and rebuild instructions. No separate solver/source download UI is added. The report export remains an output-data feature, not software distribution.

## Publish the tested site

Configure repository Settings → Pages → Build and deployment → Source: GitHub Actions once. In the existing Rust science checks workflow select branch main and suite playground-deploy. This explicit main-only invocation stages the pinned official release, runs the same browser smoke, packages only that tested site and deploys through the native github-pages environment. Ordinary pushes and pull requests never deploy. Explicit Playground smoke and deployment suites skip unrelated native compilation and portability checks; the scope classifier and read-only package rejection controls remain active. No new workflow, solver rebuild, or change to the official release is required. The deployment job fails closed if Pages is not configured or main has moved.
