# Source release automation

The versioned release request is an explicit publication decision. Update `releases/request.json` and its versioned notes in a PR after both original main workflows pass. The request pins the admitted commit, the two run IDs, exact artifact ID, artifact ZIP digest and source digest. The source revision must be an ancestor of current main, and its CLI manifest version must match the requested tag. A later infrastructure-only commit does not change the admitted source.

PR CI is read-only. A main push changing release infrastructure or the request automatically validates the original evidence and publishes the three verified source assets. The release workflow can also be rerun through workflow_dispatch on main. It must use the original CI artifact while retained; do not substitute an unverified rebuild. It verifies every required job and decisive step, including CodSpeed despite its advisory continue-on-error setting.

The write token exists only in the main publication job. It never executes artifact contents. It creates a draft, checks all three uploaded asset digests and the exact target, then publishes and checks the tag. An already published identical release is a no-op while the original artifact remains available. A conflicting tag, failed run, expired artifact, or incomplete draft stops publication; inspect the draft and recover explicitly rather than force a tag or overwrite assets. Do not edit the source target merely to release infrastructure. Future versions require a new request and version-specific notes with fresh matching CI evidence.
